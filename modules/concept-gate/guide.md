# concept-gate：概念闸门教程

## 这个模块解决什么问题

webnovel-director 原有的工作流假设：**选题已经确定，直接进入 premise → outline → 写作**。

但实际上，最多的时间浪费在 **选题阶段反复试错**——生成一个概念、写几章、发现不对、全删、重来。

concept-gate 在「选题确定」和「进入执行」之间插入一道结构化闸门。不替代创意发散，而是在发散后、投入写作前做一次系统化验证。

## 核心思想

> **不是阻止发散，而是让发散有标准可收束。**

创意阶段允许无限发散。但每次发散出候选概念后，必须过 concept-gate，用同一套标准打分。PASS 了才能进入 premise 阶段。

## 使用时机

```
方向探索 → 扫榜 → 多个概念发散 → [concept-gate] → 选定 → premise
```

## 与 premise-guard 的区别

| | concept-gate | premise-guard |
|---|---|---|
| 阶段 | 概念选择（写之前） | 执行中（写作中） |
| 问题 | 「这个选题值得写吗？」 | 「这一章偏离命题了吗？」 |
| 输入 | 一句话梗概 + 核心设定草稿 | premise.md + 章节内容 |
| 输出 | 评分 + 风险 + 竞品参考 | PASS/WARN/FAIL |
| 允许 | 推翻重来 | 不允许推翻命题 |

## 概念评分三维度

1. **市场可卖性**（30%）：这个题材现在有人看吗？
2. **可写性**（40%）：能撑起 50+ 万字吗？主角优势可持续吗？
3. **爽点清晰度**（30%）：前三章读者能懂爽点在哪吗？

## 工作流

```text
用户提出概念 → concept_gate.py --check → 6维度评分报告
  ├─ PASS (≥70分) → 进入 premise-guard
  ├─ WARN (50-69分) → 标注风险，用户决定
  └─ FAIL (<50分) → 明确拒绝理由，建议改进方向
```
